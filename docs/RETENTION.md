# سياسة الاحتفاظ والمحو

هذه السياسة تنفذها `src/persistence/retention.mjs`. السياسة معلنة في الكود
كبيانات ثابتة؛ لا تقبل الأداة اسماً خاماً لجدول SQL، بل مفاتيح السياسة المعلنة
فقط. كل قيمة وقت أو معرّف تمرر إلى PostgreSQL كمعامل، وأسماء العلاقات والأعمدة
مقتبسة ومملوكة للمحرك.

## جدول السياسة

| الجدول | أساس الاحتفاظ | نهاية المدة | الحفظ القانوني | إجراء المحو |
| --- | --- | --- | --- | --- |
| `state.data_assets` | `created_at` | `created_at + retention_days` | نعم؛ `legal_hold=true` يمنع المحو الدوري والموجّه | يحذف بعد نهاية المدة فقط |
| `state.memories` | `created_at` | `expires_at` إن كان معلناً وماضياً | نعم؛ `legal_hold=true` يمنع المحو الموجّه، وقيد المخطط يمنع تعيين `expires_at` لذاكرة محفوظة | يحذف الذكريات ذات الانتهاء الصريح الماضي فقط |
| `state.events` | `recorded_at` | لا مدة محو في هذه الخطوة | لا يوجد عمود `legal_hold` | مرفوض دائماً |

قرار `state.events` متعمد: كل حدث بعد الأول يحمل `prev_hash` لحدث سابق. حذف
بادئة قديمة يجعل أول حدث باقٍ يشير إلى تجزئة لم تعد موجودة في المرآة، وبذلك لا
تبقى السلسلة قابلة للتحقق من داخل الجدول. لذلك يفشل `purge --table events`
والمحو الموجّه بخطأ `RETENTION_EVENTS_IMMUTABLE` ولا يفتح المحرك استثناءً
لـ«بادئة». هذا ليس ادعاء دوام خارج الجدول؛ سجل الأحداث الدائم على القرص يبقى
مصدر الحقيقة كما يعرّفه المخطط.

## الحفظ القانوني

مالك قرار تعيين أو رفع `legal_hold` ليس أداة الاحتفاظ ولا عامل التشغيل الذي
يشغلها؛ إنه صاحب السلطة القانونية أو الجهة المفوضة منه، مع توثيق القرار في
الإجراء المؤسسي المناسب. وظيفة المحرك أضيق: قراءة العلم الموجود ورفض المحو
بخطأ مسمّى `RETENTION_LEGAL_HOLD`.

يظهر التقرير الجاف عدد المنتهي المسموح محوه (`eligible`) وعدد المنتهي المحمي
(`legalHoldProtected`) لكل جدول. لا يجعل التقرير صفاً محمياً قابلاً للمحو.

## الأوامر

تتطلب الأوامر وصلة معلنة، ولا يوجد افتراض لمضيف أو قاعدة:

```sh
export DATABASE_URL="postgresql://postgres@127.0.0.1:55432/postgres"
node scripts/retention.mjs
node scripts/retention.mjs plan
node scripts/retention.mjs purge --dry-run
node scripts/retention.mjs purge --table data_assets
node scripts/retention.mjs purge --table memories
```

الأمر بلا وسائط هو `plan` آمن وجاف. `purge` بلا `--dry-run` ينفذ محو الجداول
ذات السياسة القابلة للمحو (`data_assets` و`memories`) في معاملة واحدة؛ ففشل
حذف أي جدول يرجع ما سبقه. `--table` يقبل مفتاحاً معلناً فقط:
`data_assets` أو `memories` أو `events`. طلب `events` يفشل مغلقاً بالرمز
المذكور أعلاه.

تطبق الهجرة الموجودة قبل التشغيل على قاعدة جديدة:

```sh
node scripts/migrate.mjs up
node scripts/retention.mjs plan
```

## حدود معلنة / ما لم يُنجز

- **حدٌّ معلن:** لا توجد جدولة تلقائية للمحو. التشغيل قرار منفصل ومراجَع.
- **حدٌّ معلن:** لا يمحو المحرك نسخ PostgreSQL الاحتياطية أو وسائط التخزين
  الخارجية محواً آمناً؛ يلزم لها إجراء احتفاظ ومفاتيح تشفير مستقلان.
- **حدٌّ معلن:** لا توجد موافقة سيادية مؤتمتة لتعيين أو رفع الحفظ القانوني.
- **حدٌّ معلن:** لا توجد مدة احتفاظ أو محو للأحداث؛ المحرك يرفضها لحماية سلسلة
  التجزئة، ولا يدعي أنه يعيد بناء سلسلة بعد إزالة بادئة.
- **حدٌّ معلن:** الذاكرة بلا `expires_at` لا تستنتج لها مدة افتراضية؛ لا تمحى
  آلياً حتى يعلن مالك البيانات تاريخ انتهاء أو تضيف سياسة معتمدة لاحقة.
