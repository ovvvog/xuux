# الدفعة الثالثة — تمرين PostgreSQL والنسخ والاستعادة

## النطاق

استُخدم رابط Session Pooler التجريبي عبر SSL مع سلسلة شهادة مؤقتة خارج المستودع. لم تُحفظ كلمة المرور أو رابط الاتصال أو سلسلة الشهادة في المشروع أو Git.

## النتائج

| العملية | النتيجة |
|---|---|
| اتصال `psql` عبر Pooler | ناجح؛ الخادم PostgreSQL 17.6 |
| حالة دفتر الترحيلات | 18 إصداراً، الإصدار الحالي 18 |
| `npm run migrate -- status` | ناجح؛ كل الترحيلات من 0001 إلى 0018 متطابقة بالبصمة |
| `npm run backup -- create` | ناجح؛ 31 جدولاً، الإصدار 18، الزمن 568ms |
| `npm run backup -- verify` | ناجح؛ الأرشيف صالح، SHA-256 مسجل محلياً |
| `npm run restore -- ... --database state_restore_drill --force` | ناجح؛ قاعدة اختبار منفصلة أُنشئت واستعيد إليها الأرشيف |
| تحقق قاعدة الاستعادة | 31 جدولاً في مخطط `state` |
| تنظيف قاعدة الاستعادة | ناجح؛ أُسقطت قاعدة `state_restore_drill` بالقوة بعد التحقق |

## ملاحظات تقنية

احتاج `pg_dump` إلى عميل PostgreSQL 17 المطابق لخادم Supabase 17.6؛ عميل PostgreSQL 16 رفض الاتصال بفارق الإصدار. كما احتاجت أدوات PostgreSQL إلى `PGSSLROOTCERT`، بينما استخدمت طبقة Node متغير `NODE_EXTRA_CA_CERTS`، وبقي تحقق TLS مفعلاً ولم يُستخدم تعطيل للتحقق.

نجاح النسخ والاستعادة هنا مثبت على قاعدة Supabase التجريبية وبقاعدة استعادة منفصلة. لم تُجرَ عملية استعادة فوق قاعدة الإنتاج، ولم تُحذف أي بيانات من قاعدة المشروع الأصلية. هذا التمرين يثبت سلامة مسار النسخ والاستعادة الأساسي، لكنه لا يثبت بعد التعافي متعدد المناطق أو فقد الاتصال أثناء معاملة نشطة أو تلفاً متعمداً للأرشيف.

## الأسرار

استُخدمت بيانات الاتصال في متغيرات بيئية مؤقتة فقط. لا يحتوي هذا التوثيق على كلمة مرور أو Access Token أو مفتاح API أو رابط اتصال فعلي. ينبغي تدوير بيانات الاعتماد بعد انتهاء الاختبارات إذا كانت قد استُخدمت خارج بيئة خاصة.
