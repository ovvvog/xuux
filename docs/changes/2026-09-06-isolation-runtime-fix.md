# الدفعة الأولى — إصلاح runtime داخل العزل التنفيذي

## النطاق

تتضمن هذه الدفعة إصلاحاً واحداً محدوداً في `src/execution/isolation.mjs`. كان مسار الاختبار والتشغيل يستخدم أحياناً مسار Node المضيف الموجود خارج مجلد العمل، بينما كان العازل يرفض أي مسار مضيف غير مسارات النظام المربوطة مسبقاً. أدى ذلك إلى فشل اختبارات التنفيذ المسموح، لا إلى تجاوز أمني.

## التغيير المنفذ

أصبح مسار `process.execPath` المعروف فقط يُحوّل إلى `/runtime/runner` داخل بيئة العزل. يمرر المشغّل المسار المضيف إلى namespace المعزولة، ويربط **الملف التنفيذي نفسه فقط** للقراءة فقط. لا يُربط مجلد runtime المضيف، ولا يُسمح بأي مسار مضيف آخر. بقيت مجلدات النظام ومجلد العمل ومجلد `output` خاضعة لقواعد الربط السابقة، وبقي رفض المسارات غير المسموحة فعالاً.

هذا الإصلاح لا يخفف متطلبات العزل ولا يحول الرفض إلى تشغيل غير معزول. إذا غاب `unshare` أو رفضت النواة إنشاء namespaces، يبقى التنفيذ مرفوضاً مغلقاً عبر `ISOLATION_UNSUPPORTED`.

## الحدود التي بقيت معلنة

هذا التغيير يصلح مسار العزل التنفيذي ويثبت اختبارات القراءة والكتابة والمهلة والذاكرة ومحاولة الخروج في البيئة الحالية، لكنه لا يثبت وحده تشغيل Docker أو PostgreSQL أو التعافي متعدد المناطق. كما أنه لا يربط العازل تلقائياً بكل مسارات العامل الإنتاجية؛ لذلك ستُعالج هذه الوصلة في دفعة مستقلة بعد التحقق من قاعدة البيانات التجريبية.

## سلامة الأسرار

لم تُحفظ بيانات Supabase أو كلمة مرور PostgreSQL أو أي مفتاح نشر/سر في هذا الملف أو في Git. ستُستخدم بيانات الاتصال لاحقاً من متغيرات بيئية مؤقتة خارج الملفات المتتبعة، ولن تُطبع في سجلات الأوامر.
