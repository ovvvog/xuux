# ADR-0002 — إصلاح OID لمفاتيح Ed25519 في HSM (F06/F07)

- **الحالة:** مقبول (بانتظار التحقّق في بيئة WSL2 الإنتاجية)
- **التاريخ:** 2026-09-08
- **المسار والخطوة:** `WL-088` — تكامل HSM/PKCS#11
- **العلاقة:** F06 (king-signing-key)، F07 (command-ledger-signing-key)، `src/root-of-trust/pkcs11-provider.mts`، `scripts/pkcs11-keygen.mjs`، `scripts/pkcs11-eddsa-sign-probe.mjs`

## السياق

كان توقيع EdDSA داخل HSM يفشل بـ`CKR_GENERAL_ERROR` على F06/F07. أوّل فرضيّة
خاطئة كانت أنّ خلفية OpenSSL في SoftHSMv2 لا تدعم EdDSA، فقُرِّر إعادة بناء SoftHSM2
بخلفية Botan. لكنّ التتبّع المُعزول للجذر أظهر أنّ العيب ليس في SoftHSM بل في ثابت
OID داخل شيفرة المشروع نفسه.

الثابت في `scripts/pkcs11-eddsa-sign-probe.mjs` و`scripts/pkcs11-keygen.mjs` و
`src/root-of-trust/pkcs11-provider.mts` كان:

```
ED25519_EC_PARAMS = Buffer.from([0x06, 0x03, 0x2b, 0x65, 0x6e]);
// التعليق: "OID 1.3.101.110 (id-Ed25519)"
```

آخر بايت `0x6e` (= 110) يُرمِّز OID `1.3.101.110` وهو **X25519** وليس Ed25519.
الـOID الصحيح لـEd25519 هو `1.3.101.112`، آخر بايت `0x70`. النتيجة: كانت المفاتيح
تُولَّد كـX25519 تحت `CKM_EC_EDWARDS_KEY_PAIR_GEN`، ثمّ يُستدعى `C_Sign(CKM_EDDSA)`
على مفتاحٍ لا يملك القدرة على التوقيع → `CKR_GENERAL_ERROR`.

## القرار

1. **الإصلاح الفعلي:** تصحيح الثابت إلى `0x70` (OID `1.3.101.112`) في كلٍّ من
   `scripts/pkcs11-keygen.mjs` و`scripts/pkcs11-eddsa-sign-probe.mjs` و
   `src/root-of-trust/pkcs11-provider.mts`، مع **مركزة الثابت** في وحدةٍ مشتركةٍ
   واحدة `scripts/pkcs11-oids.mjs` يستوردها السكربتان، لتعذّر الانحراف مجدّداً.
   تتضمّن الوحدة حارس انحدار يتعطّل فوراً عند الاستيراد إن انزلق الثابت إلى `0x6e`.
2. **خروج الفحص بحالة صحيحة:** يُخرج `hsm:probe` رمزاً غير صفريٍّ عند أي فشلٍ في
   التوقيع أو التحقّق (كان يخرج `0` حتى عند الفشل، فيُعمي CI).
3. **حارس الاستبدال:** يرفض `--replace` تدمير المفاتيح قبل التحقّق من وجود ملف خطة
   (`--replace-plan <path>`) يحتوي أقسام النسخ/التدوير/التراجع (`backup`،`rotation`،
   `rollback`)، ويفشل قبل تحميل موديول PKCS#11 أو قراءة PIN أو الوصول إلى HSM.
4. **فحص OID للمفاتيح القائمة:** سكربت `scripts/pkcs11-existing-eddsa-sign-test.mjs`
   يقرأ `CKA_EC_PARAMS` (دون لمس المادة الخاصة) ويُبلِغ عمّا إن كان المنحنى Ed25519 أم
   X25519، ثمّ يوقّع ويتحقّق. يدعم F06 وF07 عبر `XUUX_PKCS11_KEY_ID`.

## التوافق مع المفاتيح القائمة (F06/F07)

المفاتيح الحاليّة، **إن وُلِّدت بالسكربت المتأثّر قبل الإصلاح**، هي X25519 لا Ed25519.
ولأنّها `CKA_EXTRACTABLE=false` و`CKA_NEVER_EXTRACTABLE=true`، **لا يمكن نقلها أو
تحويلها في مكانها** — يجب إتلافها وإعادة توليدها بالـOID المصحَّح.

خطورة عالية: F06 يوقّع سلسلة الدستور (تبعيّة `WL-030`/`WL-031`)، فتدويره يتطلّب
إعادة توقيع السلسلة الدستورية كاملة. لذلك **لا يجوز** استبدال F06/F07 دون خطةٍ
موثَّقة.

### خطة النسخ/التدوير/التراجع (template)

```markdown
# تدوير F06/F07 — Ed25519 OID المصحَّح

## backup
- صدّر المفاتيح العامة القائمة (PEM) قبل التدمير.
- خزّن لقطةً من توكن HSM قبل أي تعديل.

## rotation
- ولّد F06 وF07 جديدين بالـOID المصحَّح (1.3.101.112).
- أعد توقيع سلسلة الدستور بالمفتاح F06 الجديد (WL-030/WL-031).
- أعد توقيع سجل الأوامر بالمفتاح F07 الجديد.

## rollback
- استعد لقطة التوكن القديمة لو فشل التدوير.
- أبقِ المفاتيح القديمة مُسمّاةً بنسخةٍ مؤقّة حتى اكتمال التحقّق.
```

## البدائل المدروسة ولماذا رُفضت

| البديل | ما يُحسنه | لماذا رُفض هنا |
| --- | --- | --- |
| **ترقيع `oid2ByteString/byteString2Oid` في SoftHSM** | يُؤمّن فكّ OID | لا حاجة — SoftHSM يفكّ OID الصحيح بشكلٍ سليم؛ العيب كان في الثابت المُمرَّر من شيفرة المشروع، لا في SoftHSM |
| **الانتقال إلى YubiHSM2 كحلٍّ جذري** | عتادٌ يدعم EdDSA أصلاً | مُفرط بالنسبة للجذر الفعلي (OID خاطئ)؛ يُحتفظ به كخيارٍ للإنتاج عالي الحساسية إن فشل التحقّق على الخلفية الإنتاجية بعد الإصلاح |
| **تحويل المفاتيح القائمة إلى Ed25519 في مكانها** | لا إتلاف | مستحيل: `CKA_NEVER_EXTRACTABLE=true` يمنع استخراج المادّة لإعادة استيرادها |

## النتائج

**المكتسَب:** توقيع EdDSA يعمل داخل HSM (تحقّق في صندوق الرمل: `hsm:probe` PASS،
توقيع F06 وF07 المُولَّدين يمرّان مع `verify=true`)، ثابت OID مُركز ومحروس، خروج فحص
صحيح لحالة CI، وحارس يمنع الإتلاف غير المخطَّط.

**المتبقّي قبل الإغلاق:** التحقّق على بيئة WSL2 الإنتاجية (شغل `hsm:probe` ضدّ
موديول OpenSSL الإنتاجي بعد الإصلاح — إن نجح فالانتقال إلى Botan اختياري لا واجب)،
فحص OID للمفاتيح القائمة، تنفيذ خطة التدوير إن تأكّد أنّها X25519، `npm run
validate` + CI أخضر، ثمّ مراجعة Model Council المستقلّة.
