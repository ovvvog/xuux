## Item 1 — Signed authorization validity and reuse: open

The revision usefully distinguishes `provision-define-init` from `bind-initial`, specifies a domain-prefix intention, disallows algorithm negotiation, pins the verification key, and explicitly describes the host clock as a weak expiry boundary. ([E:290–296](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L290-L296))

It still does **not** select the canonicalization procedure—“مثلًا RFC 8785” is an example—or the signature algorithm, signature encoding, public-key fingerprint encoding, complete signed envelope, nonce format/entropy, or `notAfter` representation and rejection rules; “details will be settled in G3” is accurate deferral, not an implementable protocol on this commit. ([E:270–295](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L270-L295))

Only `bind-initial` has an enumerated object schema; the provisioning type lists handles, sizes, attributes, policies and certificate digest, but does not specify whether its signed bytes also include `instanceId`, the operation, schema/version, nonce and expiry, so its installation/session scope cannot be established. ([E:270–290](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L270-L290))

For the **binding digest itself**, the existing function is unambiguous: UTF-8 JSON of an ordered array containing schema, instance, both indices/Names, base, identity kind/value and both policies, so hashing exactly those bytes would cover the stated binding fields. ([fnv-binding.mts:160–176](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/fnv-binding.mts#L160-L176))

Generating a nonce does not itself establish the statement that an old authorization “does not match a new ceremony”: the verifier must compare the signed nonce to a particular active challenge and define its lifecycle, whereas the explicit verification sequence only says signature/digest/expiry/not-consumed. ([E:283–295](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L283-L295))

**Required change:** a normative schema and byte vector for each type, fixed cryptographic/encoding choices, explicit equality checks for duplicated fields, an active-challenge rule, and the durable consumption/recovery rules in item 2; this is **WL437-gpt_6_1_sol-01**.

## Item 2 — Atomic nonce consumption: open

The proposed **same-body** update is a sound building block: `#seal()` signs one body, and `writeAtomic()` writes a temporary file, optionally fsyncs it, renames it and syncs the directory, so adding binding and nonce consumption to that one body need not create a two-file commit gap. ([state-manifest.mts:1041–1049](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L1041-L1049), [state-manifest.mts:317–332](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L317-L332))

However, the design does not state that authorization freshness and nonce non-consumption are **rechecked against the current on-disk body inside the serialized critical section**; existing `bindFnvAsync` checks for a binding before queuing the seal, and the queued invariant permits an equal existing binding. ([E:283–294](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L283-L294), [state-manifest.mts:648–670](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L648-L670), [state-manifest.mts:705–766](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L705-L766))

An executable probe against this commit, using an in-memory Ed25519 test sealer, obtained **two fulfilled results for concurrent identical binds on one manifest object**; a second case with two objects for the same file obtained **two fulfilled results with bases 4 and 9**, leaving base 9 on disk, so §7.1's unqualified “two concurrent ceremonies cannot both seal, fixed in WL-434” is not supported by the existing test. ([Probe and results](./manifest-probes.mjs), [Ed25519 results](./manifest-probes-ed25519.log), [E:336](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L336))

The second case is specifically **two objects in one process**, not evidence that two different PIDs bypass the journal lock: the chain is an instance field, and the journal lock treats an existing lock owned by its own PID as removable. ([state-manifest.mts:693–702](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L693-L702), [state-manifest.mts:835–854](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L835-L854), [Ed25519 results](./manifest-probes-ed25519.log))

For `provision-define-init`, there is no sealing operation to consume the nonce, and “inventory finds the handle already defined” is only an occupancy check, not a consumed-authorization record once permitted cleanup removes a handle; the document supplies no terminal nonce state or command-budget/recovery protocol for this type. ([E:290–294](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L290-L294), [E:139–155](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L139-L155))

An interruption **strictly before step 5 begins** can leave neither binding nor consumed nonce, as described, but interruption during/after publication requires inspecting the authoritative sealed file rather than treating absence of an acknowledgment as absence of the commit. ([E:300–307](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L300-L307), [state-manifest.mts:1042–1049](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L1042-L1049))

There is also a distinct post-seal gap: `bindFnvAsync` finishes before `coordinator.bindAsync` creates its staged transaction, contrary to the table's “one serialized seal” characterization; an injected stop at that boundary left v3 with a binding, no staged transaction, no freshness anchor and no state digest, and the next declared boot failed with `STATE_MANIFEST_FNV_BINDING_IMMUTABLE`. ([production-runtime.mts:432–457](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/production-runtime.mts#L432-L457), [commit-barrier.mts:458–467](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/commit-barrier.mts#L458-L467), [Gap probe](./bind-gap-probe.mjs), [Gap results](./bind-gap-probe.log))

**Required change:** define compare-and-consume inside the seal's critical section, provisioning-token consumption independent of current index occupancy, and a distinct “binding sealed / initial coordinator commit pending” recovery state; these are **WL437-gpt_6_1_sol-03** and **-04**.

## Item 3 — TOCTOU window: open

The newly written order is materially better: acquire the shared lock before identity/material reads, validate the authorization, reread both Names and C/R immediately before sealing, then consume the nonce with the seal before releasing the lock. ([E:298–305](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L298-L305))

That closes the stated read–check–seal window **conditionally on one effective lock domain**, but item 4's unspecified coverage and namespaces prevent establishing that condition for all relevant writers; the current coordinator and manifest seal chains do not themselves supply it. ([E:298–307](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L298-L307), [commit-barrier.mts:412–430](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/commit-barrier.mts#L412-L430), [state-manifest.mts:693–715](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/state-manifest.mts#L693-L715))

Between ceremony and next boot, the design correctly requires another EK-based session and pinned-material checks; the runtime also checks the freshness epoch/anchor rather than relying only on the original signature, so the document does not establish an acceptance path merely by saying an unauthorized TPM change is detected later. ([E:61–68](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L61-L68), [E:307](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L307), [production-runtime.mts:432–481](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/production-runtime.mts#L432-L481))

The remaining failures are incomplete locking proof and incomplete post-binding recovery, **not** evidence that the added final reread is useless or that atomic commit across the TPM and filesystem is available. ([E:329–337](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L329-L337), [Gap results](./bind-gap-probe.log))

**Required change:** complete **WL437-gpt_6_1_sol-02** and **-04**, and describe exactly which final-state checks and recovery states apply after lock release.

## Item 4 — Cross-process ceremony lock: open

The replacement of the probe's file protocol by an OS-released lock is a reasonable direction, but “flock, or a named Windows object” does not specify its canonical resource identity, namespace, location/ACLs, acquisition timeout, lock order/reentrancy, or how a Windows service, WSL clients, containers and additional hosts are forced into the same ownership domain. ([E:298–307](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L298-L307), [E:343](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L343), [E:397](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L397))

The existing probe locks only `advanceState`, using a pathname derived from its configured `lockDir` and counter index; material acquisition and `read()` are outside that lock, while the coordinator queue is per object and its manifest stages/promotions occur outside the socket's advance lock. ([nv-state-bound-socket.mjs:234–249](/tmp/wt-d3d5e1f9-gpt/sim/freshness-nv/nv-state-bound-socket.mjs#L234-L249), [nv-state-bound-socket.mjs:383–424](/tmp/wt-d3d5e1f9-gpt/sim/freshness-nv/nv-state-bound-socket.mjs#L383-L424), [commit-barrier.mts:412–430](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/commit-barrier.mts#L412-L430), [commit-barrier.mts:458–531](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/commit-barrier.mts#L458-L531))

The assertion that the current probe's `O_EXCL` lock remains stuck when its process dies is inaccurate: it reads the owner PID, tests liveness, removes a dead owner's lock, and has a timeout, although that protocol still has PID-reuse, empty-file and namespace limitations that an OS-owned lock should avoid. ([E:343](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L343), [nv-state-bound-socket.mjs:391–416](/tmp/wt-d3d5e1f9-gpt/sim/freshness-nv/nv-state-bound-socket.mjs#L391-L416))

The “+1” read only checks interference up to that read; it cannot establish that every bypassing writer is detected if a different writer changes C/R after the check and before the final R write, so it is not a substitute for the missing common lock. ([E:343](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L343), [nv-state-bound-socket.mjs:454–468](/tmp/wt-d3d5e1f9-gpt/sim/freshness-nv/nv-state-bound-socket.mjs#L454-L468))

**Required change:** one TPM-owning broker/lock authority, or a specified equivalent; canonical lock identity and access control; explicit rejection of unsupported multi-host/container configurations; participation by every relevant TPM/manifest writer; bounded acquisition and recovery rules; and tests with actual separate processes and namespaces, not only two promises on one object; this is **WL437-gpt_6_1_sol-02**.

## Item 5 — Successful/error TPM response parsing: holds

For well-formed commands emitted by the allowed TPM 2.0 command gate, the revised split matches the specification: ordinary non-success responses have a ten-byte no-sessions form, while successful responses use the command tag, bounded lengths, response HMAC/rpHash checks for session-bearing commands and updated TPM nonces. ([E:159–170](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L159-L170), [TCG Part 3 §§4.4, 5.9, 6.1](https://trustedcomputinggroup.org/wp-content/uploads/TCG_TPM2_r1p64_Part3_Commands_15may2021.pdf), [TCG Part 1 §§18.2, 19.6.7](https://trustedcomputinggroup.org/wp-content/uploads/TCG_TPM2_r1p59_Part1_Architecture_pub.pdf))

A salted HMAC/policy session does require a valid HMAC even with an empty object authorization value; the empty-response-HMAC cases for password or unbound/unsalted empty-key sessions are not reasons to weaken the intended salted profile. ([E:153](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L153), [E:226–227](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L226-L227), [TCG Part 1 §§19.4, 19.6.15](https://trustedcomputinggroup.org/wp-content/uploads/TCG_TPM2_r1p59_Part1_Architecture_pub.pdf))

The no-transport-resend rule for mutating commands, unknown-outcome handoff, and TBS `0x80280400` stop rule are explicit; the coordinator then resolves unknown outcomes by reading the state and only retrying the state-level operation with the same arguments, with a bounded eventual fence. ([E:172–180](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L172-L180), [commit-barrier.mts:535–574](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/commit-barrier.mts#L535-L574))

**Boundary of this verdict:** Part 3 §6.1 has the legacy `TPM_RC_BAD_TAG`/`TPM_ST_RSP_COMMAND` exception for an *invalid outbound command tag*; the gate should never emit such a command, and that response must remain a terminal error, not a path to accepting unsigned successful data. ([TCG Part 3 §6.1](https://trustedcomputinggroup.org/wp-content/uploads/TCG_TPM2_r1p64_Part3_Commands_15may2021.pdf))

The parser still needs implementation tests, including valid/invalid HMACs, nonce handling, size/trailing-byte errors and error-form responses; that is an acknowledged future deliverable, not evidence currently available for L-B. ([E:383–385](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L383-L385))

## New findings

### WL437-gpt_6_1_sol-01 — high — §6.3: authorization protocol still has non-normative and unscoped parts

- **Finding:** the binding envelope and provisioning field list do not together define one exact signed protocol, and a nonce's creation is asserted to prevent old-ceremony reuse without a complete verifier/lifecycle rule. ([E:270–295](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L270-L295))
- **Proposed fix:** select a concrete serialization and signature profile; specify both full schemas and encodings; include type/version/installation/resource identity/challenge/expiry; define exact active-challenge checks, unknown-field/duplicate-field handling and test vectors, including cross-installation and cross-type substitutions.

### WL437-gpt_6_1_sol-02 — high — §6.3, §7.2: lock domain and writer coverage are not defined

- **Finding:** the specified lock is only a host-side recommendation with no common namespace or enforcement plan, while existing queues/locks cover different portions of the transaction; the probe-death and universal +1-detection claims are also overstated. ([E:298–307](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L298-L307), [E:343](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L343), [nv-state-bound-socket.mjs:391–416](/tmp/wt-d3d5e1f9-gpt/sim/freshness-nv/nv-state-bound-socket.mjs#L391-L416))
- **Proposed fix:** choose the TPM-owning lock/broker location and canonical key; cover all mutating ceremonies, advances and relevant manifest operations; define permissions, timeout, process death, lock order and reentrancy; reject unsupported multiple-host/container arrangements; test separate processes and namespace splits.

### WL437-gpt_6_1_sol-03 — medium — §6.3, §7.1: same-body persistence is not a complete compare-and-consume protocol

- **Finding:** the claimed existing one-winner behavior does not hold for equal simultaneous binds, nor for two manifest objects in the same process, and provisioning occupancy is not a durable nonce-consumption record. ([E:294](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L294), [E:336](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L336), [Ed25519 results](./manifest-probes-ed25519.log))
- **Proposed fix:** check and consume against the current sealed state under the same lock that publishes it; reject a second execution even for identical material; define a terminal provisioning authorization record/command budget and cleanup policy; add equal-material, multiple-object and multiple-process cases.

### WL437-gpt_6_1_sol-04 — medium — §6.3, §7.1–7.2: missing recovery state after binding seal and before coordinator staging

- **Finding:** the existing operations are not one seal, and stopping between them leaves a bound v3 file that the declared restart tries to bind again and rejects with `IMMUTABLE`; future nonce consumption in the first seal would make the recovery distinction more important, not eliminate it. ([E:336](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L336), [production-runtime.mts:452–457](/tmp/wt-d3d5e1f9-gpt/src/root-of-trust/production-runtime.mts#L452-L457), [Gap results](./bind-gap-probe.log))
- **Proposed fix:** define a durable initial-binding transaction state and an explicit authorized continuation that reuses the identical sealed binding without consuming a new bind authorization or allowing rebinding; fault-inject before/after each publication, staging and TPM transition boundary.

### WL437-gpt_6_1_sol-05 — medium — §4.3: incomplete command/session profiles can reject valid intended operations or permit unrelated resources

- **Finding:** the gate lacks complete restrictions for several allowed commands and the non-authorizing-session attributes required by TPM processing; a diagnostic swtpm experiment demonstrated the attributes error independently of salt/HMAC correctness. ([E:130–155](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L130-L155), [Results](./session-attribute-probe.log), [TCG Part 3 §5.5](https://trustedcomputinggroup.org/wp-content/uploads/TCG_TPM2_r1p64_Part3_Commands_15may2021.pdf))
- **Proposed fix:** enumerate every command's handles, auth roles, parameter bytes/ranges, tags and session attributes, especially audit sessions, empty private input for the service public key, owned-resource-only FlushContext, fixed policyRef and exact salt/EK profile; reject before submission and supply positive as well as negative tests.

### WL437-gpt_6_1_sol-06 — medium — §3.2, §4.3: certified-key-to-salt-key equality is left implicit

- **Finding:** the enumerated boot sequence does not explicitly join certificate validation/digest pinning to the actual public key selected for session salting, leaving an implementation ambiguity at the trust boundary rather than a demonstrated exploit of an existing backend. ([E:61–66](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L61-L66), [E:153](/tmp/wt-d3d5e1f9-gpt/docs/adr/0007-annex-e-production-backend-design.md#L153))
- **Proposed fix:** require RSA modulus/exponent or ECC curve/point congruence with the validated certificate's SPKI, validate the expected EK public template/Name, and salt only to that exact key; add certificate-A/public-key-B substitution tests on every boot/reconnect.
