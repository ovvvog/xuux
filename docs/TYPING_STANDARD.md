# معيار التوثيق النوعي — المسار M2.00

**الغرض:** الكود يعمل على `node:test` بلا خطوة بناء، فالأنواع تُكتب بـ **JSDoc** ويفحصها `tsc` بـ `checkJs`. هذا يعطي صرامة TypeScript الكاملة بلا تصريف وبلا تغيير سطر واحد من السلوك.

**السبب الذي أوجب هذا المعيار:** قبل M1 كان `tsc` ينجح دائماً لأنه يمرّ على 140 ملف `.ts` **كلها تعليقات فقط** — نجاح كاذب لا يفحص شيئاً. حين صارت الشجرة بيانات وانكشف الكود الحقيقي، ظهرت **240 مخالفة نوعية**. هذا المعيار هو ما تُصفَّر به.

---

## القواعد الملزمة

### 1. لا إسكات، بل تصحيح

**ممنوع منعاً باتاً:**

- `@ts-ignore` و`@ts-expect-error` و`@ts-nocheck`
- `/** @type {any} */` أو `@param {any}` كحلّ للتخلص من خطأ
- إضعاف `tsconfig.json` (إسقاط `strict` أو `noUncheckedIndexedAccess` أو `exactOptionalPropertyTypes`)
- تغيير سلوك الكود لإرضاء الفاحص

المخالفة النوعية إما **نوع ناقص** فيُكتب، أو **عيب حقيقي** فيُصلح ويُسجَّل في سجل الأعمال. لا خيار ثالث.

الاستثناء الوحيد المقبول: `@ts-expect-error` **داخل اختبار** يُثبت أن الاستدعاء الخاطئ يُرفع خطأً في زمن التشغيل — ويجب أن يُرفق بتعليق عربي يشرح أن الخطأ النوعي هو **المقصود من الاختبار**.

### 2. النوع يُعرَّف في الوحدة المالكة للمفهوم، لا في ملف مركزي

كل مفهوم يُعرَّف بـ `@typedef` **داخل الوحدة التي تملكه**، ويُستورد عند الحاجة عبر `import()`:

```js
/** @typedef {import('../root-of-trust/crown.mjs').CrownGateway} CrownGateway */
```

وليس في ملف أنواع مركزي. السبب: الملف المركزي يصير نقطة تنازع يلمسها كل تغيير، ويفصل النوع عن الكود الذي يصفه فيتعافران مع الوقت. أما تكرار **شكل** الكائن نفسه في أكثر من دالة فممنوع: يُسمّى مرة واحدة بـ `@typedef` ويُشار إليه بالاسم.

### 3. كل معامل عام له نوع معلَن

```js
/**
 * يُصدر شهادة لهوية وكيل.
 * @param {string} subject - معرّف الموضوع
 * @param {AgentRole} role - الدور المطلوب
 * @param {string[]} [capabilities=[]] - القدرات الممنوحة
 * @returns {Certificate}
 */
issue(subject, role, capabilities = []) { … }
```

### 4. حقول الصنف تُعلَن في المُنشئ إن كانت قيمتها الأولى `null` أو `[]` أو `new Map()`

```js
constructor() {
  /** @type {string | null} */
  this.reason = null;
  /** @type {Map<string, Task>} */
  this.tasks = new Map();
}
```

بلا هذا يستنتج الفاحص `null` أو `Map<any, any>` فتنهار كل استخدامات الحقل بعدها.

### 5. `noUncheckedIndexedAccess` مُشدَّد — والقراءة بمؤشّر تُرجع `T | undefined`

لا تُسكِت الخطأ بعلامة `!`. تعامل مع الاحتمال صراحةً:

```js
const first = lines[0];
if (first === undefined) throw new Error('EMPTY_INPUT');
```

أو أعلن أن الغياب مقبول:

```js
/** @type {string | undefined} */
const maybe = parts[1];
```

استخدام `!` مسموح فقط إذا كان الغياب **مستحيلاً بحكم سطر سابق في نفس الدالة** — وحينها يُرفق تعليق يذكر ذلك السطر.

### 6. الكائنات المُفكَّكة في المعاملات تُوصَف ككائن واحد

```js
/**
 * @param {{ crown: CrownGateway, log: EventLog, policy?: PolicyEngine | null }} deps
 */
constructor({ crown, log, policy = null } = {}) { … }
```

هذا ما يُصلح `TS7031` (عنصر مُفكَّك ضمني) و`TS2353` (خاصية غير معروفة في كائن خيارات) معاً.

### 7. اقرأ خصائص `unknown` بعد تضييقها لا قبله

`JSON.parse` يُرجع `any`، والخطأ الملقوط في `catch` يُرجع `unknown`:

```js
} catch (err) {
  const message = err instanceof Error ? err.message : String(err);
}
```

## كيف تتحقّق

```bash
npm run typecheck          # الإعداد الأساسي وفيه checkJs مُفعَّل — يجب أن يكون نظيفاً
                           # (تقاعد tsconfig.strict.json في WL-004 لأنه صار مطابقاً للأساسي)
npm test                   # السلوك لم يتغيّر: كل الاختبارات ما زالت تنجح
npm run validate           # السلسلة الكاملة
```

**معيار القبول المزدوج:** صفر خطأ نوعي **و** كل الاختبارات ناجحة. تصفير الأخطاء بتغيير السلوك ليس نجاحاً بل خرقاً للمادة 2 من [القاعدة الحاكمة](../GOVERNANCE_RULE.md).
