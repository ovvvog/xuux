# النسخ الاحتياطي والاستعادة — M3.07

هذه أداة نسخ PostgreSQL فعلية، لا ملفاً قالبياً. بُنيت `scripts/backup.mjs` و
`scripts/restore.mjs` من الصفر؛ لم يوجد `scripts/restore.sh` على القرص، ولذلك لم
يكن هناك بديلٌ له.

## ما يُنسخ

- كل مخطّط `state`: تعريفاته وجداوله العشرة وبياناتها وفهارسها وقيودها وتسلسله.
- دفتر الهجرات `public.schema_migrations` مع صفوفه. لأن اختيار `--schema state`
  و`--table public.schema_migrations` يتقاطع في `pg_dump`، تُضمّنه أداة النسخ
  في جدول مرحلي مولّد داخل الأرشيف ثم تنقله أداة الاستعادة إلى `public` بالاسم
  الصحيح قبل المقارنة.
- ملف `*.dump.manifest.json` الملاصق للنسخة: وقت البدء، المدة بالمللي ثانية،
  إصدار PostgreSQL، نسخة الهجرة، SHA-256 للملف، وعدد صفوف كل جدول.

## ما لا يُنسخ

- مخطّطات وجداول التطبيق خارج `state`، ولا الأدوار أو كلمات المرور أو الامتيازات
  (`--no-owner` و`--no-privileges`).
- WAL ولا سجل PostgreSQL الكامل ولا إعدادات الخادم العامة.
- تشفير الملف أو نقله إلى تخزين خارج الجهاز.

## أوامر التشغيل

تُعلن الوصلة صراحة؛ لا تختار الأداتان قاعدة افتراضية:

```sh
export DATABASE_URL="postgresql://postgres@127.0.0.1:55432/postgres"
node scripts/backup.mjs create
node scripts/backup.mjs verify backups/state-....dump
node scripts/restore.mjs backups/state-....dump --database state_restore_clean
```

يمكن تمرير مسار واضح بدلاً من مسار `create` الافتراضي:

```sh
node scripts/backup.mjs create /tmp/state.dump
node scripts/restore.mjs /tmp/state.dump --database state_restore_clean
```

تنشئ الاستعادة قاعدة الهدف إن لم توجد. وترفض قاعدة تحتوي `state` أو
`public.schema_migrations` بالرمز `RESTORE_TARGET_NOT_CLEAN`، ولا تمحوها إلا مع
`--force` الصريح. بعد `pg_restore` تقيس الأداة عدّ الصفوف ونسخة الهجرة في البيان؛
أي عدم تطابق يفشل برمز مسمّى غير صفري.

## تمرين الاستعادة

شُغّل الاختبار الحقيقي، لا محاكاة له، بالأمر:

```sh
export DATABASE_URL="postgresql://postgres@127.0.0.1:55432/postgres"
node --test tests/persistence/backup-restore.test.mjs
```

ينشئ الاختبار قاعدة مصدر معزولة، يطبق الهجرات، ويكتب صفاً صالحاً في كل جدول من
الجداول العشرة، ثم ينشئ نسخة `-Fc` ويستعيدها إلى قاعدة معزولة نظيفة. يثبت تساوي
عداد الصفوف، وبصمة JSONB مرتبة للمحتوى، وصورة الكتالوج (الأعمدة والقيود والفهارس)،
ونسخة الهجرة. ويثبت أيضاً رفض الهدف المشغول بلا `--force` ورفض `verify` لملف عُدّل
بعد البيان وطباعة زمن الاستعادة.

## أزمنة مقيسة فعلياً

في PostgreSQL `18.6 (Ubuntu 18.6-0ubuntu0.26.04.1)` المحلي، شُغّل التمرين المنفصل
التالي في 2026-08-23:

```sh
node scripts/backup.mjs create /tmp/m307-cli.dump
node scripts/backup.mjs verify /tmp/m307-cli.dump
node scripts/restore.mjs /tmp/m307-cli.dump --database m307_cli_restore
```

كان المصدر على نسخة الهجرة 2، وفيه 10 جداول و1 صف إجمالاً (صف واحد في `agents`
وصفر في التسعة الأخرى). خرج التنفيذ الفعلي كما يأتي:

- زمن النسخ: **74 مللي ثانية**.
- حجم `/tmp/m307-cli.dump`: **37,212 بايت**.
- زمن الاستعادة إلى `m307_cli_restore` التي أنشأتها الأداة: **70 مللي ثانية**.
- المقارنة بعد الاستعادة: 10 جداول، 1 صف في `agents`، ونسخة الهجرة 2.
- SHA-256 الذي تحقق منه `verify`:
  `3529ea2803b3c22299f99100ddf124c13951c783c36caa171c32fec927ad5ada`.

هذه قياسات تجربة واحدة بهذا الحجم، وليست تقديراً لأداء إنتاج أو ضماناً لزمن
استعادة أكبر.

## ما لم يُنجز / حدود معلنة

- **حدٌّ معلن:** لا جدولة دورية أو تدوير احتفاظ مؤتمت للنسخ.
- **حدٌّ معلن:** لا استعادة نقطة-زمن (PITR) ولا نسخ WAL.
- **حدٌّ معلن:** لا تخزين خارج الجهاز ولا اختبار استعادة من وسيط بعيد.
- **حدٌّ معلن:** لا تشفير لملف النسخة؛ SHA-256 يكشف التعديل ولا يحمي السرية.
- **حدٌّ معلن:** يجب أن تتاح قاعدة `postgres` الإدارية على الخادم كي تنشئ الأداة
  قاعدة هدف غير موجودة.
